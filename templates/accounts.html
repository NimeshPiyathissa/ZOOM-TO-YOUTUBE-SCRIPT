No password, code or token is ever stored by this system. Each account is just a label plus its own private Chrome profile on the VPS. You sign in yourself, by hand, in that Chrome window over the remote desktop; the dashboard only opens the window and afterwards asks Google whether a session exists. Removing an account deletes its profile directory (and the session with it).

Creates an empty Chrome profile. Nothing is signed in until you do it yourself in the next step.

Sign in:

  1. A Chrome window has opened on the remote desktop at Google's sign-in page. If you only see a black screen, wait a few seconds; if asked, enter the VNC password.
  2. Sign in on the touchscreen exactly as you would on a phone: email, password, then any 2-Step prompt. Type into the remote desktop, not this page.
  3. If Google says "This browser or app may not be secure": that's Google's automation check. This window is opened without any automation hooks, so it's usually the new-device/datacenter-IP signal instead. Tap Try another way and approve on your phone, or use a backup code. If it still refuses, sign in to the same account once from your phone or PC, then retry here within a few minutes - Google relaxes the check for a recently-approved account. Turning on 2-Step Verification with phone prompts makes this far more reliable.
  4. Extra verification prompts (phone tap, code by SMS/app, recovery email) are expected on a first sign-in from this machine - complete them on the remote desktop.
  5. When you can see your account avatar in the top-right of Google, tap I'm done. The window closes so the session is saved, then the dashboard asks Google to confirm it. Nothing you typed is kept anywhere.
